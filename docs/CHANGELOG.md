# Changelog

All notable changes to ATLAS CLIENT are recorded here. The archive is a single `ATLAS_CLIENT.mcaddon` containing the Behavior Pack and Resource Pack; `ATLAS.mcaddon` is kept as an identical compatibility copy.

---

## 1.9.0 — Full audit and HUD/data fixes

### Added

- **Waypoint search** by name, ID, dimension, coordinates or kind, with result
  count, a clear-search action and no mutation of the stored list.
- **Server Manager search** by name, address, port, description, category or
  region while keeping add/edit/delete/reorder reachable.
- **Real movement data**: official `getVelocity()` speed in blocks/s plus
  sprint/sneak/jump/fly/glide state. It is never derived from invented input.
- **Official armor totals** (`totalArmor`, `totalToughness`) on the ARMOR screen.
- **Held-item details** on ITEMS: real amount and the selected hotbar slot.
- **Potion level I** is now displayed instead of being hidden; levels use Roman
  numerals consistently.
- **ESPCHEST interaction time** in the detail screen.
- **HUD page shortcuts** for armor, effects and totem panels, and an explicit
  statement that FPS/Ping are not exposed by the Script API.
- **DIAGNOSTICS scope text** separating an API probe, a function call and a real
  user-visible feature test.
- `ATLAS_CLIENT.mcaddon` is now the documented install file. The old
  `ATLAS.mcaddon` name is generated byte-for-byte identically for compatibility.

### Fixed

- ESPCHEST deduplication previously compared only the newest row. It now scans
  the whole recent log for the same block, dimension and type within a
  three-second window, so alternating between nearby containers cannot create
  duplicate history.
- World-scoped caches (settings, combat, containers, servers, waypoints) are
  cleared on `worldLoad`, so moving to another world cannot reuse the previous
  world's data.
- Closing or leaving while the menu is active no longer leaves the re-entrancy
  guard stuck for that player ID.
- Player death/hurt handlers now tolerate missing event fields instead of
  throwing outside the event boundary.

### Changed

- Main menu order matches the specification: HOME, HUD, VISUAL, PLAYER,
  MOVEMENT, ARMOR, ITEMS, POTIONS, TOTEMS, COMBAT, WAYPOINTS, ESPCHEST,
  SERVER MANAGER, SETTINGS, DIAGNOSTICS, ABOUT.
- Version bumped to **1.9.0** in `package.json`, both manifests, module and
  dependency versions, the validator and the runtime.
- All 1.8.0 features, `ATLAS1`/`ATLAS2` compatibility and stored data formats
  are preserved.

### Verification

- `npm run check` — passed: typecheck, **30 tests**, **321 mocked form flows**,
  51-file/99.7 KiB build, **7 validation checks**.
- Both `ATLAS_CLIENT.mcaddon` and `ATLAS.mcaddon` contain the same BP/RP,
  manifests, scripts and assets, with no nested or junk entries.
- **Not tested inside Minecraft, on iPhone, PS5, a Realm, BDS for 1.9.0,
  Bedrock Arab or Mega10.** The BDS evidence in this repository belongs to
  1.8.0. See [`TEST_REPORT.md`](TEST_REPORT.md).

## 1.8.0 — Verification and failure-isolation release

### Fixed

- **A form API failure could be recorded as `WORKING`.** `safeShow()` now throws a
  `FormShowError` after reporting the failure, so the router records `ERROR` for
  that section instead of treating a screen that never opened as a success.
  A form that stays busy after all retries is handled the same way.
- **Waypoint details failed completely when `getViewDirection()` was unavailable.**
  The detail screen now keeps the real distance and cardinal bearing and omits
  only the optional relative left/right label.
- **One broken player could stop locator sync for everyone else.**
  `syncAllLocators()` now isolates each player; the remaining players still get
  their locator markers.
- **The delayed spawn setup was outside the event guard.** A failure in the
  post-spawn callback is now logged as an event error instead of escaping as an
  unhandled timeout exception.

### Added

- Regression coverage for every accepted command name (`/atlas`,
  `/atlas:atlas`, `/atlas:menu`, `/menu`), form failure/`ERROR` reporting,
  waypoint detail without the view API, per-player locator isolation and the
  delayed spawn guard.
- Full 1.8.0 test report with static checks, the Node.js harness, official
  Creator Tools validation and a real Bedrock Dedicated Server 1.26.60.6 run.

### Changed

- Version bumped to **1.8.0** in `package.json`, both manifests, module and
  dependency versions and the runtime.
- All 1.7.0 HUD, input, armor, effects, totems, waypoints, ESPCHEST, combat,
  Server Manager, compatibility, themes, Arabic/English and settings behavior is
  preserved. `ATLAS2`/`ATLAS1` settings remain compatible.

### Verification

- `npm run check` — passed: typecheck, **27 tests**, **292 mocked form flows**,
  51-file/95.0 KiB build, 6 validation checks.
- Official Minecraft Creator Tools `validate addon` — 0 errors, 0 warnings,
  0 recommendations.
- Bedrock Dedicated Server 1.26.60.6 — pack loaded as 1.8.0, scripts started,
  10 event handlers and both commands registered, `worldLoad` received, all four
  command names resolved, three `/reload` cycles stayed clean, and a ~64-second
  soak kept RSS stable with no add-on errors.
- **Not tested in a player UI, on iPhone, PS5, a Realm, Bedrock Arab or Mega10.**
  See [`TEST_REPORT.md`](TEST_REPORT.md).

## 1.7.0 — Command entry-point fix

### Fixed

- **`/atlas` was never registered.** Bedrock requires a namespace in every custom command name, so 1.6.0 only registered `atlas:menu` (`/atlas:menu`). The add-on now also registers `atlas:atlas`, which Minecraft exposes as **`/atlas`** and `/atlas:atlas`; `atlas:menu` also provides Bedrock's automatic `/menu` chat alias.
- Command registration is now attempted per name, so a collision or an unsupported registry disables only that entry point instead of the whole command path.
- A missing registry, a failed registration or a repeated startup event no longer risks a duplicate or half-registered command.
- The command callback accepts the player from `sourceEntity` or `initiator`, rejects console/command-block origins with a readable message, and catches form errors.

### Added

- **DIAGNOSTICS** shows the command names Minecraft actually accepted, their short chat aliases, the menu item and the optional scriptevent path. Registration is reported separately from execution: the command feature becomes `WORKING` only after a player runs it.
- **EXPORT DIAGNOSTICS** includes an `Entry points:` line, so a missing command can be reported without guessing.
- A dedicated command test suite covers both names, the `/atlas` alias, the alias callback, a name collision and a missing registry.

### Changed

- Version bumped to **1.7.0** in `package.json`, both manifests, module versions, dependency versions and the runtime.
- Welcome, boot, HUD, about and error strings now show `/atlas` as the short form and `/atlas:menu` as the canonical command.
- Documentation explains that commands exist only while ATLAS is active in that world, and that a public server must run the pack itself.
- Every 1.6.0 HUD, input, armor, effects, totems, waypoints, ESPCHEST, combat, Server Manager, compatibility, themes, Arabic/English and settings behavior is preserved. `ATLAS2`/`ATLAS1` settings remain compatible.

### Verification

- `npm run check` — passed: typecheck, **27 tests** (including a new command suite), **279 mocked form flows**, 51-file/94.5 KiB build, 6 validation checks.
- `unzip -t ATLAS.mcaddon` — passed.
- **Not tested inside Minecraft, on iPhone, PS5, a Realm, BDS or a public server.** The alias behavior is documented Bedrock behavior, not an in-game test result.

## 1.6.0 — Universal compatibility release

### Added

- **ATLAS UNIVERSAL COMPATIBILITY ENGINE** (`scripts/compatibility.js`) and a pure feature-status model (`scripts/compatibilityModel.js`).
- Per-feature states: `WORKING`, `LIMITED`, `READY`, `UNAVAILABLE`, `ERROR` and `NOT TESTED`. `WORKING` requires a real successful operation in the current script session; `NOT TESTED` is never counted as success.
- Lifecycle handling for `worldLoad`, player join, respawn, leave, dimension change and a deferred world-ready fallback. Reinitialization keeps settings, waypoints and the ESPCHEST log, and does not add duplicate listeners, tick loops or commands.
- Capability gating in the HUD, armor alerts and health alerts so a missing optional API disables only that element.
- Bounded error tracking by category (script, event, storage, form) with a last-check tick and recent-error list.
- **DIAGNOSTICS** now lists every feature status, required/optional API gaps, engine counters and reinitialization counts.
- **EXPORT DIAGNOSTICS** produces a copyable chat report in bounded chunks; the report contains no passwords, tokens or Microsoft account data.
- Unit tests for the feature/status model, report formatting and chat chunking; integration coverage for diagnostics export and for a second `worldLoad` plus respawn without duplicated listeners.

### Changed

- Version bumped to **1.6.0** in `package.json`, both manifests, module versions, dependency versions and the runtime.
- All 1.5.0 HUD, input, armor, effects, totems, waypoints, ESPCHEST, combat, Server Manager, themes, Arabic/English, settings and diagnostics behavior is preserved.
- `ATLAS2` settings codes and legacy `ATLAS1` import remain compatible.

## 1.5.0 — Server Manager release

### Added

- **SERVER MANAGER** section in `/atlas:menu`, kept separate from the rest of the client.
- Per-player server address book with add, edit, delete, reorder, favourites, category and region label.
- Validation for IPv4 addresses, domain names and ports 1–65535; duplicate host/port and blank names are rejected.
- Manual **current server** mark with a UTC last-marked timestamp, plus a **Direct Join** form that remembers the last address and port.
- **Connection guide** with the exact host/port and the official manual steps, plus **Send address to chat** because add-ons have no clipboard access.
- One dedicated `atlas_servers` menu icon.
- Unit tests for the server model and integration coverage for add/edit/delete/order/favourite/mark, invalid input, duplicates, Direct Join and persistence after leave/rejoin.
- [`docs/SERVERS.md`](SERVERS.md) with the supported scope, platform steps and limitations.

### Explicitly not added

- No CONNECT button, auto-reconnect switch or fake ONLINE/OFFLINE/ping/player-count/version data. Minecraft's stable Script API has no networking, server-list, transfer or connection-observation API for world add-ons. `@minecraft/server-admin.transferPlayer` is dedicated-server-only, experimental and unavailable on clients/Realms, so it is not used.
- No clipboard control and no way to open Minecraft's Add Server screen.
- No Microsoft-login, allow-list, anti-cheat or PS5 restriction bypass. PS5 has no Add Server button; SERVER MANAGER cannot change the console UI.

### Changed

- Version bumped to **1.5.0** in `package.json`, both manifests, module versions and the runtime.
- All 1.4.0 HUD, input, armor, effects, totems, waypoints, ESPCHEST, combat, themes, Arabic/English, diagnostics and settings behavior is preserved. Settings codes remain `ATLAS2-...` with legacy `ATLAS1-...` import; server data is stored separately.

### Verification

- `npm run typecheck` — passed.
- `npm test` — 16 tests passed, including 271 mocked form flows.
- `npm run build` — produced a 48-file `ATLAS.mcaddon` (78.5 KiB).
- `npm run validate` — passed 6 checks, including every JSON file, manifests, UUIDs, textures, imports and ZIP contents.

## 1.3.0 — development release

### Added

- **Home summary** in the main menu: player name, world day and online player count where available.

- **HUD editor coverage** for the session timer and the Visual/PvP action-bar elements.

- Health is no longer shown as `0/20` when the health component cannot be read.
- Totem counts rebuild on inventory changes, coalescing bursts within a 5-tick window.

- Version bumped to **1.3.0** in both manifests, modules, dependencies, `package.json` and the runtime.
